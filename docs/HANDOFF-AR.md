# تسليم مشروع وصل

## محتويات التسليم

- تطبيق React للعملاء وتطبيق Angular لموظفي الدعم والمديرين.
- دعم العربية والإنجليزية وتبديل RTL/LTR.
- إعداد Supabase مشترك مع سياسات عزل البيانات والصلاحيات والمرفقات الخاصة.
- اختبارات ووثائق تشغيل وREADME باللغة الإنجليزية.
- نسخة مبنية للتجربة الفورية داخل ملف التحميل، وسجل Git قابل للاستعادة من ملف bundle.

## الخطوة التي تحتاج تنفيذها في حسابك

تم وضع رابط مشروعك والمفتاح المنشور في إعدادات التطبيقين. المفتاح المنشور لا يسمح بإنشاء الجداول أو المستخدمين إداريًا.

1. افتح مشروع `vbsrwnjyiskbjangbohb` في لوحة Supabase.
2. افتح SQL Editor ونفّذ ملف `supabase/setup.sql` كاملًا **مرة واحدة** على مخطط لا يحتوي جداول متعارضة. خذ نسخة احتياطية إذا كان المشروع مستخدمًا بالفعل.
3. أنشئ حسابات الاختبار من Authentication → Users، كما هو موضح في `docs/BACKEND.md`، وعيّن أدوار الموظفين والمدير باستخدام SQL المرفق هناك.
4. اضبط Site URL وروابط إعادة التوجيه.
5. شغّل التطبيقات وسجّل الدخول بالبريد وكلمة المرور التي اخترتها.
6. شغّل `npm run test:live` بعد تعبئة `.env.live` للتحقق من التكامل الحقيقي.

لا تحتاج إلى إرسال كلمة مرور قاعدة البيانات أو مفتاح إداري لأي شخص. إذا اخترت أداة إنشاء الحسابات، ضع مفتاح الإدارة محليًا فقط داخل `.env.seed` المستبعد من Git.

## التشغيل السريع للنسخة المرفقة

بعد فك الضغط، افتح مجلد `wasl-support`:

```bash
node scripts/serve.mjs
```

ثم افتح:

- العملاء: `http://localhost:4173/customer/`
- الدعم: `http://localhost:4173/support/`

النسخة المبنية موجودة في الأرشيف. لتطوير المشروع أو إعادة بنائه:

```bash
npm ci
npm run build
npm run preview
```

استخدم Node.js 22 LTS. للمطورين، `npm run dev` يشغّل React على 5173 وAngular على 4200.

## التجربة قبل إعداد قاعدة البيانات

استخدم أزرار «جرّب كعميل» و«جرّب كموظف» و«جرّب كمدير». البيانات تجريبية وتُحفظ في المتصفح فقط. لتجربة انتقال الطلب بين التطبيقين استخدم رابطَي المنفذ 4173 في نفس المتصفح. المرفقات تحتاج وضع الاتصال الحقيقي بـSupabase.

الواجهة باللغة الإنجليزية أولًا؛ زر «العربية» يبدّل اللغة ويحفظ الاختيار. محتوى الطلبات الذي أدخله المستخدم لا تُترجمه المنصة آليًا.

## الرفع إلى GitHub مع الحفاظ على الـcommits

بجوار مجلد المصدر يوجد `wasl-support.bundle`. من المجلد الذي يحتوي هذا الملف:

```bash
git clone wasl-support.bundle wasl-platform
cd wasl-platform
git log --oneline --reverse
```

أنشئ مستودعًا فارغًا في GitHub دون README إضافي. ثم استبدل اسم المستخدم والمستودع:

```bash
git remote remove origin
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git branch -M main
git push -u origin main
```

أمر push واحد يرفع **كل الـcommits العشرة**. لا تحتاج إلى رفع يدوي متكرر أو إنشاء تاريخ وهمي. ملف `docs/GITHUB.md` يحتوي الخطوات والتحقق من الملفات السرية بالتفصيل.

الأكواد المكتوبة للمشروع منسّقة ولا تحتوي تعليقات داخلية. الشرح موجود في الوثائق. التعليقات والإشعارات القانونية التي قد تنتجها أدوات البناء لمكتبات خارجية ليست جزءًا من الأكواد المصدرية المكتوبة للمشروع.

## حدود التحقق

تم اختبار البناء، قواعد البيانات داخل PostgreSQL مضمّن، وسير العمل التجريبي في المتصفح. تم التحقق من وصول المفتاح المنشور إلى خدمة Auth في مشروعك، لكن **لم يتم تطبيق SQL على مشروعك أو إنشاء حسابات فعلية أو اختبار التخزين الحي** لعدم توفر صلاحية إدارية. لا تعتبر مرحلة التشغيل الحي منتهية قبل تنفيذ الخطوات السابقة واجتياز اختبارها.

راجع `docs/VERIFICATION.md` للنتائج و`README.md` للقيود التشغيلية المعروفة.
